# Day 96: Evaluation-Ready Demo Script

## Objective

Provide a short, polished demonstration that proves the Aegis platform is a complete software-first digital twin and estate automation system, ready for evaluation or degree submission.

## Demo prerequisites

Before the presenter starts:

- Backend is running on `http://localhost:8001`
- Frontend is running on `http://localhost:3000`
- Demo login is prepared:
  - Email: `admin@aegis.com`
  - Password: `admin1234`
- At least one tenant and default estate data are loaded
- Real-time telemetry is active and dashboard cards are visible

## Recommended demo flow (10-15 minutes)

### 1. Opening and project overview (1 minute)

Present the project as a working software-first digital twin platform for smart estates and operational automation.

Key framing points:
- multi-tenant estate management
- live digital-twin simulation
- automation scheduling and control
- health monitoring and recommendations
- real-time dashboard + 3D visualization
- architecture ready for future hardware integration

### 2. Login and dashboard landing view (2 minutes)

Open the frontend and sign in.

Show:
- estate overview cards
- current health status
- active alerts
- connected systems and sensors
- operational summary widgets

Narration:
> This is the live command surface for the estate. We can see the system status, active health signals, and operational context from a single dashboard.

### 3. Live estate health and telemetry (2 minutes)

Open the estate dashboard and highlight:
- overall system health
- zones, devices, and sensor status
- telemetry trends and recent readings
- severity-aware alerts

Call out examples including:
- environmental readings
- device availability
- alert levels and resolution flow

Narration:
> The platform is not static mock UI; it is actively surfacing telemetry and health states from the estate simulation and API layer.

### 4. Digital twin and 3D scene view (2.5 minutes)

Open the 3D dashboard or scene management view.

Show:
- estate layout
- object/entity placement
- live scene entities and status colors
- system details when selected
- movement or state changes as the digital twin updates

Narration:
> This gives the user a visual representation of the estate as a live, simulated operating environment rather than just numbers on a table.

### 5. Control and automation actions (2 minutes)

Open the system-control or task-scheduler area.

Show:
- a control command being issued
- a sensor/device or robot action being triggered
- task state changes and status output
- the automation flow behind it

Narration:
> The system supports operational control commands, automation tasks, and real-time device interactions in a tenant-aware environment.

### 6. Alerts, recommendations, and summary layer (2 minutes)

Move to the alert or recommendations view.

Show:
- active alerts
- recommendation or maintenance suggestions
- system summary insights
- how the environment responds under change

Narration:
> This is the decision-support layer: the platform not only reports state, but also gives actionable guidance and operational context.

### 7. Close with project readiness statement (1 minute)

Conclude with the core message:
- project is functionally complete in software
- the architecture supports real-world extension
- the solution is evaluation-ready and demo-ready
- future hardware integration is a clean extension, not a redesign

---

## Suggested presenter wording

> Aegis is a software-first digital twin and smart-estate platform. The system demonstrates live estate monitoring, real-time simulation, operational controls, automation workflows, and actionable recommendations in a single tenant-aware architecture. The project is complete as a functioning digital twin platform and is ready for evaluation, presentation, and future hardware integration.

## Demo success criteria

The demo is successful if it shows all of the following:

- dashboard loads and is responsive
- live estate health data is visible
- alerts are visible and understandable
- control and automation actions can be triggered
- 3D/digital-twin view shows a live environment
- system is clearly presented as a complete platform, not a partial prototype
